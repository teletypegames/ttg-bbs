# Siliconia BBS

A telnet board of the Teletype Games BBS network, powered by
[rubbs](https://git.teletypegames.org/engines/rubbs). Generated by `devarea/scripts/new-bbs.sh`
from the house template (`devarea/procedures/bbs-server-creation.md`): replace the notices with
what the board is about.

It has two faces on one port, like every board of the network:

- a **modern** one for ANSI terminals: a desktop under a menubar, windows and the mouse;
- a **Commodore 64** one in PETSCII, 40×25: a cursor menu, lists and pages.

## Running

The board is `boards/siliconia` of [TTG BBS](https://git.teletypegames.org/bbs/ttg-bbs) and runs
with the other boards in one container. From the repository root:

**Docker Compose** (every board, this one on 2338):

```bash
docker compose up --build
```

**Directly (Ruby 3.x):**

```bash
bundle install
bin/board siliconia                              # this board alone, on 2338 (boards.yml)
cd boards/siliconia && bundle exec ruby bbs.rb   # on BBS_PORT or 2323
```

Connect:

```bash
telnet localhost 2338      # compose, bin/board
telnet localhost 2323      # bbs.rb on its own (BBS_PORT)
```

## Configuration

`env-example` lists the variables with their defaults; in Docker the root `compose.yaml` sets the
ones that differ (a secret from the root `.env`, on the server the stack's `.env`):

| Variable | Default | Description |
|---|---|---|
| `BBS_PORT` | `2323` | TCP port to listen on (in the container the supervisor sets 2338 from `boards.yml`) |
| `BBS_MAX_SESSIONS` | `100` | Callers at once (`boards.yml` sets 50) |
| `SILICONIA_BBS_NOTICES` | `config/notices.yml` | The notices |
| `TTG_CENTRAL_URL` | `http://ttg-gate-bbs:8090` | The network's Central (TTG Gate BBS), where feedback and the wall live |
| `RUBBS_AUTH_SECRET` | — | The secret every board of the network shares (in `.env` on the server) |

## Project structure

```
bbs.rb                         entry point: Rubbs.board (title, domain, preset, faces)
config/notices.yml             the notices
lib/domain.rb                  requires the domain in dependency order
lib/domain/
  model/notice_model.rb        a notice
  repository/notice_repository.rb  config/notices.yml
  service/notice_service.rb    the board's rules
  siliconia_bbs.rb        the board's domain (SiliconiaBBS, a Rubbs::Common::Board::Domain)
lib/ui/
  logo.rb                      the board's word in rubbs' Rubbs::Common::Text::BlockFont
  modern.rb                    UI::Modern::APP: the rubbs Application
  petscii.rb                   UI::Petscii < Rubbs::Petscii::Face: the C64 board
test/                          the domain's tests
```

## Logs

Every line on stderr starts with the log tag `siliconia-bbs:` (rubbs' `Rubbs.log`). In the container
they are in `docker logs ttg-bbs`, with `"board":"siliconia-bbs"`.

## Tests

In `boards/siliconia`:

```bash
bundle exec rake test              # the tests
bundle exec rake                   # the tests and rake bbs:check
```

## Deploy

A push to master of bbs/ttg-bbs deploys every board from Woodpecker: RuboCop, the tests, a compose
check, then `ci-deploy ttg-bbs` on the server (infra/host-config), which runs the stack in
`/srv/stacks/ttg-bbs` (container `ttg-bbs`); `boards/siliconia/data/` and `.env` stay. A change
only in `boards/siliconia` restarts only this board. The image runs the rubbs revision of the root
`Gemfile.lock`, as uid 1000.
